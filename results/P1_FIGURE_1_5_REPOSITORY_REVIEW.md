# P1 Figure 1–5 repository review

## Scope and source availability

This review uses the repository only. The repository does not contain the manuscript's Figure 1 architecture image, Figure 2 dual-mode diagram, their editable sources, or the manuscript DOCX. None of the tracked branches `main`, `codex/p1-main-integration`, or `codex/p1-multibus-powerflow` contains these assets. Their original layout, colors, fonts, and components therefore cannot be verified or edited faithfully from repository files. No replacement artwork was generated.

The repository's numbering differs from the manuscript numbering: the fleet-deployment plot corresponding to manuscript Figure 5 is `results/figure_6_grid_resilience_fleet_deployment_all_cases.png/.pdf`. The repository's `figure_5_energy_supply_demand_mismatch.png/.pdf` is an input-data supply–demand plot, not a five-truck dispatch result. It remains unchanged, as do all other Figure 3–16 artifacts.

## P1 content required when the original Figure 1–2 assets are available

- **Figure 1:** retain the architecture; label the main truck ESS as both a Mode 1 economic resource and a Mode 2 emergency backup resource. In Mode 2, available main and auxiliary HFC trucks dispatch first; the main truck ESS supplies only remaining demand, subject to its output, available energy, and physical minimum SOC. Any remaining demand is unserved.
- **Figure 2:** retain the Mode 1 branch and visual design. The Mode 2 branch must communicate `HFC-First Dispatch → ESS Backup (if needed) → Residual Unserved Energy`. The shared SOC/LOH constraint remains applicable; the ESS backup reduces subsequent SOC. The Mode 2 ESS floor is the physical minimum SOC of 0.1, distinct from the Mode 1 economic discharge entry threshold of 0.3.

These are editing specifications, not substitutes for the unavailable figures.

## Manuscript Figure 5 verification

The plotted data are read from `results/p1_main_hourly.csv`, generated by `HB-MPS main simulation.py` through `main_p1_adapter.simulate_main_p1(..., trucks=5)`. `draw_grid_resilience` plots industrial load, the Mode 2 threshold and active hours, plus `Active_Trucks - 1` as additional trucks. The saved CSV has 168 hourly rows per α scenario. A direct CSV check found:

| α | Mode 2 hours | Maximum active trucks | Maximum additional trucks | HFC energy (MWh) | ESS emergency energy (MWh) | Residual unserved (MWh) |
|---:|---:|---:|---:|---:|---:|---:|
| 1.3 | 39 | 5 | 4 | 26.403 | 4.560 | 29.993 |
| 1.5 | 8 | 1 | 0 | 1.570 | 0 | 0 |
| 1.8 | 0 | 0 | 0 | 0 | 0 | 0 |

Every plotted Mode 2 marker matches the stored load > threshold condition; all actual deployments stay within the five-truck limit. At α=1.3, 19 Mode 2 hours have zero HFC trucks dispatched because the physical fleet has no available HFC energy at those hours. The red Mode 2 markers indicate demand events, not necessarily successful supply; zero blue bar height is therefore expected. The ESS backs up supply in 11 hours.

The repository plot was regenerated in a temporary directory from the saved P1 CSV using its original plotting function. Its PNG pixels exactly matched the tracked `results/figure_6_grid_resilience_fleet_deployment_all_cases.png` (3870 × 4245 × 4 RGBA; maximum channel difference 0). The four existing `tests/test_p1_main_integration.py` tests passed, including the five-truck physical-path comparison. **No Figure 5 regeneration or data change is needed.**
